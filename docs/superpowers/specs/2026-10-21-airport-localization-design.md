# 机场数据库本地多语言与增量维护设计

状态：已按用户选择改为预先翻译、存入项目的本地语言数据库，待书面设计审阅。尚未修改运行代码，也未调用付费翻译。

## 目标与范围

覆盖项目已有的 en、es、ru、zh-CN、zh-TW、ja、ko。地图机场名称、机场详情、搜索候选与定位结果使用同一套译名；包括机场名称、所在城市、地区及导航台名称。国家名复用现有按 ISO 国家代码本地化的机制。机场和导航台的代码、频率、坐标、数值及原始来源保持不变。

当前本地快照：86,258 个机场，11,008 个导航台，249 个国家/地区。机场原始名称有 81,654 种；城市去重必须结合国家和地区，不能把不同地区的同名城市误合并。关闭机场的记录仍保留，与当前显示规则一致。

## 已选择的翻译方式

由我们预先整理并翻译名称，按语言存入项目内的机场语言数据库，随部署发布到自己的 VPS。用户无需提供翻译文件。运行中的应用不调用千问或其他翻译服务，也不启用付费的全库翻译任务。

已确立的通用译名优先；没有通用译名的设施采用一致的音译及机场类别术语。专名在不同语言中允许按惯例保留，但不能仅替换 Airport 等后缀就宣称完成了整条名称翻译。参照公开名称时须核对实体身份，不能仅凭同名或不唯一的代码匹配；语言回退的英文结果不得充当已确认的目标语言译名。

## 数据结构与存储

保留现有 OurAirports 原始 CSV、快照与校验信息。译文以独立语言数据保存到项目，并种入 VPS 持久目录，部署不能覆盖持久更新。语言数据按语言和稳定记录 ID 分片；只写变化的分片，并原子发布版本清单。浏览器只访问本项目服务器。

翻译项包含：实体类型、稳定 ID、字段、目标语言、原文指纹、必要的国家/地区上下文、译文、来源、翻译规范版本、状态与更新时间。机场身份使用 OurAirports 数字 ID；导航台使用其独立 ID 命名空间。人工修订保留审计记录，优先级高于批量导入。相同城市/地区的译名按语义上下文复用。

## 增量规则

1. 源版本变化后，以稳定 ID 比较新增、删除和字段变化，产生持久的待翻译清单。服务器定时检测源版本并更新清单；翻译维护在发布流程中完成，不由服务器自行调用模型。
2. 指纹按需翻译字段及其身份上下文计算，不使用整条记录或整个源版本号作为失效条件。坐标、海拔、频率变化不触发名称重译。
3. 仅新增、改名、缺少目标语言或明确要求重新处理的字段进入清单。导出这些字段完成翻译后，再校验并增量导入对应语言数据库。已完成项目复用；重复导入幂等。新原文已替代的旧译文不得发布。
4. 源数据和译文分别拥有版本。源更新但名称没变时继续使用已有译文；只改某个语言的某个字段时，其他语言与字段不失效。
5. 原始 CSV 上游仍可能整份下载；不能把本地增量处理宣称成上游具有逐行差量接口。

## 显示、搜索与缓存

地图、详情、候选、选择上下文统一通过名称解析器取值。切换语言只读取本地译文并更新文字，保持相机、图层、选择目标和实体身份。前端按语言与译文版本缓存，迟到响应不得覆盖用户的新语言选择。名称缺失时显示原文，并记录真实覆盖状态。

搜索同时保留原文、目标语言译名及 ICAO/IATA 等代码检索；中文、日文、韩文等无空格查询也应可命中。普通城市搜索仍走原有地名定位，重复代码或模糊机场名称保留明确选择。

## 翻译维护与发布

首次全库按语言生成本地文件，并检查代表性机场、直升机坪、水上机场、同名城市和导航台。后续只导出差异清单，保留已经完成的译文。导入命令校验记录 ID、语言、字段与原文指纹，先验证完整批次，再原子发布受影响分片和版本清单；失败不影响正在使用的语言数据库。

页面浏览、地图移动、搜索和切换语言只请求本项目服务。两个 VPS 实例共享持久语言数据库，通过写入锁和原子发布避免损坏。原始机场更新可独立完成；尚未翻译的新名称临时显示原文，列入待处理清单。来源文本属于数据，不能作为执行指令。报告有效译文与原文回退的实际数量；不得将部分样本或回退原文报告为全库翻译完成。

## 验证标准

- 同一源版本重复处理，新增待翻译项为零；仅坐标变化也为零。
- 一个名称字段变更，只使其受影响的语言翻译失效。
- 清单重启、多实例并发和重复导入不会丢失译文；旧原文的导入批次被拒绝。
- 所有现有语言热切换后，地图、已打开详情与搜索候选显示一致，相机和选择保持不变。
- 本地语言、原文和代码搜索可定位同一稳定 ID。
- 阻断 GitHub、Wikidata 和翻译供应商后，已有数据仍可正常浏览；前端没有这些外部请求，后台也没有付费翻译调用。
- 分别报告每个语言与字段的有效覆盖、待处理、失败和人工修正数量。
